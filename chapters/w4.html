🛒 頻繁樣式探勘與 Apriori

頻繁樣式探勘是找出資料中常常一起出現的項目組合，再從這些組合產生「X ⇒ Y」的關聯規則；Apriori 是逐層找頻繁項目集的經典演算法。

  • 問題情境是購物籃分析（Market Basket Analysis）：哪些商品常被一起買？
  • 用支持度（Support）篩出頻繁項目集，再用信賴度（Confidence）篩出強規則（Strong Rule）。
  • 用閉合（Closed）與極大（Maximal）頻繁項目集壓縮結果。
  • Apriori（1994, VLDB）利用「頻繁項目集的子集必頻繁」的性質，逐層產生候選並剪枝。

1. 本章摘要

  • 頻繁樣式（Frequent Pattern）是資料中常常出現的組合，本章聚焦在頻繁項目集（Frequent Itemset）與關聯規則（Association Rule）。
  • 購物籃分析的結果可用來做組合包、推薦、促銷與貨架擺放。
  • 在 KDD 流程中屬於「資料探勘」步驟，是描述型探勘。W6 會講 Apriori 的改良與 FP-Growth。

2. 核心概念

2.1 頻繁樣式的種類

  • 頻繁項目集（Frequent itemset）：常在同一筆交易一起出現的項目，例如 {Milk, Bread}。
  • 序列樣式（Sequential pattern）：常依特定順序發生的事件（講義用繪本《如果你給老鼠吃餅乾》比喻）。
  • 結構樣式（Structured pattern）：常出現的子結構，例如子圖、子樹。

2.2 關聯規則（Association Rule）

關聯規則 \(X \Rightarrow Y\) 的意思是：含有 X 的交易，也傾向含有 Y；它描述「共同出現」，不是因果關係。

  • X 是前項（Antecedent），Y 是後項（Consequent），要求 X、Y 非空且 \(X \cap Y = \varnothing\)。
  • 判斷是不是合法規則（第 13 頁）：X、Y 都是全部項目 I 的非空子集，而且不相交。例如 I = {a, b, c, d, e} 時，{a, c} ⇒ {d} 兩個條件都成立。
  • 可用在交易資料，也可用在關聯式資料，例如 {Age = 20–29} ⇒ {Buys = Laptop}。
  • 講義的例子：{Milk, Bread} ⇒ {Butter}。

2.3 交易資料庫與 k-項目集

  • 交易資料庫（Transactional Database, TDB）：由多筆交易組成，每筆有唯一的交易編號（TID）和一組項目。有些應用還會記錄每個項目的數量。
  • 項目集（Itemset）：一組項目；k-項目集（k-itemset）是含 k 個項目的項目集，例如 {a, b, c} 是 3-項目集。

2.4 支持度與信賴度

支持度回答「這個組合在整個資料庫裡有多常見」；信賴度回答「看到 X 時，有多大把握也看到 Y」。

  • 絕對支持度（支持計數，Support count）：含有 X 的交易筆數；相對支持度：含有 X 的交易比例。
  • 頻繁項目集：支持度不小於最小支持度門檻（min_sup，σ）的項目集。
  • 強規則：同時滿足 min_sup 與最小信賴度 min_conf，即「夠常見也夠可靠」。
  • 限制：兩者只顯示一起出現的頻率，不衡量相關性或因果；要看正負相關可用提升度（Lift，見第 4 節）。

2.5 為什麼先找頻繁項目集？

  • 因為 \(\text{support}(X \Rightarrow Y) = \text{support}(X \cup Y)\)，規則要滿足 min_sup，\(X \cup Y\) 就必須是頻繁項目集。
  • 所以每條強規則一定來自某個頻繁項目集：先找出全部頻繁項目集，再把每個項目集拆成前項與後項即可。
  • 難處：min_sup 低時頻繁項目集會爆量，而且頻繁項目集的子集都頻繁，結果大量重複。這就是要壓縮成閉合或極大的原因。

2.6 閉合與極大頻繁項目集

閉合頻繁項目集是「沒有任何真超集的支持度跟它一樣」的頻繁項目集；極大頻繁項目集是「沒有任何真超集是頻繁的」的頻繁項目集。

  • 閉合保留精確的支持度資訊，是無損壓縮：若 X 不閉合，就有更大的 Y 支持度相同，回報 Y 就能推回 X 的支持度。
  • 極大壓縮得最多，但只知道哪些頻繁、不知道子集的精確支持度，是有損壓縮。
  • 三者關係：極大 ⊆ 閉合 ⊆ 頻繁。

講義勘誤

  • 第 29 頁閉合的條件 a 寫成「A is a proper superset of B」，方向反了，應為「B 是 A 的真超集」；同頁「there exists a larger itemset B ⊂ A」也應為 B ⊃ A。正確定義：不存在 B ⊃ A 使 sup(B) = sup(A)。
  • 第 32 頁極大的條件 b 寫成「B is not frequent」，應為「B is frequent」。正確定義：不存在頻繁的 B ⊃ A（同頁下方的數學式是對的）。

2.7 Apriori 性質（Apriori Property）

Apriori 性質：頻繁項目集的所有非空子集都一定頻繁；反過來說，不頻繁項目集的所有超集都不頻繁。

  • 例子：{beer, diaper, nuts} 頻繁，則 {beer, diaper} 也頻繁，因為含前者的交易一定含後者。
  • 反單調性：\(\text{sup}(X \cup \{A\}) \le \text{sup}(X) < \text{min\_sup}\)。
  • 剪枝的依據：只要候選的某個子集不頻繁，就不必掃資料庫計算它的支持度。

3. 演算法與方法

3.1 關聯規則探勘兩階段

  1. 找出所有頻繁項目集（例如用 Apriori）
  2. 從頻繁項目集產生規則，只保留信賴度 ≥ min_conf 的

3.2 Apriori 演算法

Apriori 是逐層（level-wise）找頻繁項目集的演算法：用頻繁 k-項目集 \(L_k\) 產生 (k+1)-候選，剪掉不可能頻繁的，再掃資料庫計數。

  • 每一層兩步：連接（Join）\(C_{k+1} = L_k \bowtie L_k\)，剪枝（Prune）刪掉有不頻繁 k-子集的候選。
  • 剪枝在掃描資料庫之前，不用計數就能刪。
  • 重複到 \(L_{k+1} = \varnothing\) 為止。
  1. 掃描資料庫，計算每個項目的支持計數，得到頻繁 1-項目集 \(L_1\)
  2. 連接（Join）：只有「前 k−1 個項目相同、最後一個項目較小者在前」的兩個項目集才能連接
  3. 剪枝（Prune）：候選只要有一個 k-子集不在 \(L_k\) 裡，就先刪掉，不用計數
  4. 掃描資料庫，計算剩下候選的支持計數，保留 ≥ min_sup 的成為 \(L_{k+1}\)
  5. 重複步驟 2～4，直到 \(L_{k+1} = \varnothing\)，輸出所有 \(L_k\) 的聯集
Apriori(D, min_sup):
    L1 = { 支持計數 >= min_sup 的 1-項目集 }
    k = 1
    while Lk 不是空集合:
        Ck+1 = Join(Lk)                    # 前 k-1 項相同才連接
        for c in Ck+1:
            if c 的某個 k-子集不在 Lk:
                從 Ck+1 刪除 c              # Prune
        for t in D:                        # 掃描一次資料庫
            for c in Ck+1 且 c ⊆ t:
                c.count += 1
        Lk+1 = { c in Ck+1 | c.count >= min_sup }
        k = k + 1
    return L1 ∪ L2 ∪ ... ∪ Lk
  • 為什麼要字典序（Lexicographic order）：確保同一個候選只會被產生一次。
  • \(L_{k+1} \subseteq C_{k+1}\)：頻繁 (k+1)-項目集一定來自候選集。直接對每個候選計數也可以，但候選多時掃描成本很高，所以先剪枝再計數（第 50 頁）。
  • 連接例子：{a, b, c, d} ⋈ {a, b, c, e} → {a, b, c, d, e}；{a, b, c} 和 {a, b, d} 可連接成 {a, b, c, d}；前 k−1 項不同就不能連接；前 k−1 項相同但 \(l_1[k] > l_2[k]\)（順序反了）也不連接，因為同一組在順序正確時已經連接過一次。
  • 時間複雜度 補充：最壞情況候選數是指數級（d 個項目最多 \(2^d - 1\) 個項目集）；若最長頻繁項目集長度為 k，大約需要掃描資料庫 k+1 次。
  • 優點：觀念簡單、實作容易，利用剪枝大量減少候選。缺點：需要多次掃描資料庫；min_sup 低時候選數量爆炸。
  • 參數：min_sup 越低 → 頻繁項目集越多、跑越久；min_sup 太高 → 可能漏掉有趣但少見的組合。min_conf 只影響規則產生階段，不影響頻繁項目集。

3.3 從頻繁項目集產生規則

  1. 對每個大小 ≥ 2 的頻繁項目集 l，列出所有非空真子集 s
  2. 產生候選規則 \(s \Rightarrow (l - s)\)
  3. 計算信賴度 = support_count(l) ÷ support_count(s)
  4. 信賴度 ≥ min_conf 就保留
  • 一個 k-項目集可產生 \(2^k - 2\) 條候選規則（例如 {a, b, c} 有 6 條）。
  • 不需要再檢查支持度，因為 l 本來就頻繁。頻繁項目集及其支持計數可存在雜湊表裡，查分母很快。

產生強規則

接續上面 Apriori 元件的資料與 min_sup。預設 9 筆交易、min_conf = 60% → 強規則 10 條，與講義第 69 頁一致。

4. 公式整理

4.1 支持度

$$\text{support}(X) = \frac{|\{T \in D : X \subseteq T\}|}{|D|}, \qquad \text{support}(X \Rightarrow Y) = \text{support}(X \cup Y)$$

分子就是支持計數。陷阱：\(X \cup Y\) 是「項目的聯集」，意思是「同時含有 X 和 Y 的交易」，不是「含 X 或含 Y」。

4.2 信賴度

$$\text{confidence}(X \Rightarrow Y) = P(Y \mid X) = \frac{\text{support\_count}(X \cup Y)}{\text{support\_count}(X)}$$

陷阱：分母是前項 X；講義的「66%」其實是 2/3 ≈ 66.7%，若 min_conf = 66% 還算通過，若 min_conf = 67% 就不通過。

4.3 反單調性、閉合與極大

$$X \subseteq Y \Rightarrow \text{sup}(Y) \le \text{sup}(X)$$ $$X \text{ closed} \iff X \text{ frequent} \wedge \nexists\, Y \supset X : \text{sup}(Y) = \text{sup}(X)$$ $$X \text{ maximal} \iff X \text{ frequent} \wedge \nexists\, Y \supset X : Y \text{ frequent}$$

4.4 提升度 補充

$$\text{lift}(X \Rightarrow Y) = \frac{\text{confidence}(X \Rightarrow Y)}{\text{support}(Y)} = \frac{P(X \cup Y)}{P(X)P(Y)}$$

大於 1：正相關；等於 1：獨立；小於 1：負相關。講義第 4 頁只提到名稱，細節應該會在後續課程說明。

例一：支持度與信賴度（講義 4 筆交易：a,c,d / b,c,d,e / a,b,c,d / a,d，min_sup = 50%、min_conf = 66%）

  1. 頻繁 1-項目集：{a} 75%、{b} 50%、{c} 75%、{d} 100%（{e} 25% 不頻繁）
  2. 頻繁 2-項目集：{a, c} 50%、{a, d} 75%、{b, c} 50%、{b, d} 50%、{c, d} 75%（{a, b} 25% 不頻繁）
  3. 頻繁 3-項目集：{a, c, d} 50%、{b, c, d} 50%；沒有頻繁 4-項目集
  4. {a} ⇒ {d}：支持度 = sup({a, d}) = 3/4 = 75%；信賴度 = 3/3 = 100%
  5. {d} ⇒ {a}：支持度 75%；信賴度 = 3/4 = 75%
  6. {a, c} ⇒ {d}：支持度 = 2/4 = 50%；信賴度 = 2/2 = 100%
  7. {c, d} ⇒ {a}：支持度 50%；信賴度 = 2/3 ≈ 66.7%
  8. {b} ⇒ {a, c}：支持度 = sup({a, b, c}) = 1/4 = 25%；信賴度 = 1/2 = 50% → 兩個門檻都不過 待確認講義第 19～23 頁的項目字母是數學字型，文字擷取後無法辨識，這條是依數字反推的：支持度 25%、信賴度 50% 的規則符合 {b} ⇒ {a, c}。若講義實際寫的是 {d} ⇒ {a, c}，正確值應為 s = 50%、c = 50%。
  9. 強規則是第 4、5、6、7 條

例二：Apriori 完整流程（講義 9 筆交易，min_sup count = 2）

  1. 第一次掃描得 \(C_1\)：a:6、b:7、c:6、d:2、e:2、f:1 → \(L_1\) = {a}, {b}, {c}, {d}, {e}（f 只有 1 次被淘汰）
  2. 連接得 \(C_2\) 共 10 個；2-項目集的子集都是頻繁 1-項目集，沒有可剪枝的
  3. 掃描計數：ab:4、ac:4、ad:1、ae:2、bc:4、bd:2、be:2、cd:0、ce:1、de:0 → \(L_2\) = {a, b}, {a, c}, {a, e}, {b, c}, {b, d}, {b, e}
  4. 連接得 \(C_3\)：abc、abe、ace、bcd、bce、bde
  5. 剪枝：ace 含 ce、bcd 含 cd、bce 含 ce、bde 含 de，這些 2-子集都不在 \(L_2\)，刪掉；剩 abc、abe 四個候選不用掃資料庫就被刪掉了，這就是 Apriori 性質省下的工夫。
  6. 掃描計數：abc = 2（008、009）、abe = 2（001、008）→ \(L_3\) = {a, b, c}, {a, b, e}
  7. 連接得 \(C_4\) = {a, b, c, e}；剪枝時發現 ace、bce 不在 \(L_3\) → 刪掉，\(L_4 = \varnothing\)，結束
  8. 產生規則（min_conf = 60%）：來自 \(L_2\) 的 a⇒b、a⇒c、c⇒a、c⇒b（4/6）、e⇒a、d⇒b、e⇒b（2/2）通過；b⇒a、b⇒c（4/7）、a⇒e（2/6）、b⇒d、b⇒e（2/7）不通過
  9. 來自 {a, b, c}：六條信賴度 2/6、2/7、2/6、2/4、2/4、2/4，全部低於 60%
  10. 來自 {a, b, e}：e⇒ab、ae⇒b、be⇒a（2/2）通過；a⇒be、b⇒ae、ab⇒e 不通過 → 強規則共 10 條，與講義第 69 頁一致

6. 易混淆處

比較項目AB判斷關鍵
支持度 vs. 信賴度支持度：\(X \cup Y\) 在全部交易的比例信賴度：含 X 的交易中也含 Y 的比例分母是 |D| 還是 sup(X)
絕對 vs. 相對支持度絕對：筆數（如 3）相對：比例（如 75%）min_sup 給的是整數還是百分比
頻繁項目集 vs. 強規則頻繁項目集：只看支持度強規則：支持度與信賴度都要過是項目集還是有方向的規則
閉合 vs. 極大閉合：沒有「支持度相同」的超集，無損極大：沒有「頻繁」的超集，有損超集是比支持度還是比是否頻繁
連接 vs. 剪枝連接：用 Lk 產生 Ck+1剪枝：刪掉有不頻繁 k-子集的候選剪枝在掃描資料庫「之前」，不用計數
X⇒Y vs. Y⇒X支持度相同信賴度通常不同信賴度分母跟著前項變
共同出現 vs. 因果關聯規則：只說一起出現因果：一個導致另一個規則不能直接解讀成因果

7. 複習問題

7.1 選擇題

1. Apriori 中，候選 {a, c, e} 會被剪枝的原因是？（\(L_2\) = {a, b}, {a, c}, {a, e}, {b, c}, {b, d}, {b, e}）

(C)。{a, c, e} 由 {a, c} ⋈ {a, e} 產生，但它的子集 {c, e} 不在 \(L_2\)，所以在計數之前就被剪掉。

2. 哪一種壓縮能還原所有頻繁項目集的精確支持度？

(B)。閉合是無損壓縮；極大只能還原「哪些頻繁」，不知道子集的精確支持度。

3. 一個頻繁 4-項目集最多能產生幾條候選規則？

(D)。\(2^4 - 2 = 14\)：扣掉空集合和自己，其他每個子集都可以當前項。

1. 用自己的話解釋 Apriori 性質，並說明它如何幫助剪枝。

頻繁項目集的子集一定頻繁；反過來說，只要有一個子集不頻繁，整個項目集就不可能頻繁。所以候選只要有一個 k-子集不在 Lk，就可以在掃描資料庫前直接刪掉。

2. Apriori 連接步驟為什麼要求「前 k−1 個項目相同」且項目依字典序排列？

看解答
確保每個 (k+1)-候選只由一組「共享前 k−1 項」的項目集產生一次，不會重複。而且任何頻繁 (k+1)-項目集去掉最後一項或倒數第二項得到的兩個 k-子集都在 Lk，所以不會漏。

3. 一條規則支持度與信賴度都很高，就代表 X 導致 Y 嗎？

看解答
不代表。支持度與信賴度只說明一起出現的頻率，不是因果。例如 Y 本來就很常見時，信賴度自然就高，甚至可能是負相關（補充可用 Lift 檢查）。

7.3 計算題

下列題目共用這份資料：T1 = {A, B, C}、T2 = {A, C}、T3 = {A, D}、T4 = {B, C, E}、T5 = {A, B, C, E}。可以把上面 Apriori 元件的資料切到「複習題 5 筆交易」驗算。

1. 計算 {B} ⇒ {C} 與 {C} ⇒ {B} 的支持度與信賴度。

看解答
B 出現在 T1、T4、T5（3 筆），C 出現在 T1、T2、T4、T5（4 筆），BC 同時出現在 T1、T4、T5（3 筆）。{B}⇒{C}：支持度 60%，信賴度 3/3 = 100%。{C}⇒{B}：支持度 60%，信賴度 3/4 = 75%。

2. 以 min_sup count = 2 執行 Apriori，列出每一層的 C 與 L；再以 min_conf = 70% 列出由 {B, C, E} 產生的強規則。

看解答
C1：A:4、B:3、C:4、D:1、E:2 → L1 = {A, B, C, E}。C2：AB:2、AC:3、AE:1、BC:3、BE:2、CE:2 → L2 = {AB, AC, BC, BE, CE}。連接得 C3 = {ABC, BCE}，子集都在 L2 不用剪；計數 ABC:2、BCE:2 → L3 = {ABC, BCE}。ABC 與 BCE 前兩項不同無法連接，C4 = ∅。由 {B, C, E}：B⇒CE 2/3 ✗、C⇒BE 2/4 ✗、E⇒BC 2/2 ✓、BC⇒E 2/3 ✗、BE⇒C 2/2 ✓、CE⇒B 2/2 ✓。強規則：E⇒BC、BE⇒C、CE⇒B。

3. 承上題，找出所有閉合頻繁項目集與極大頻繁項目集。

看解答
頻繁：A:4、B:3、C:4、E:2、AB:2、AC:3、BC:3、BE:2、CE:2、ABC:2、BCE:2。閉合：A、C、AC、BC、ABC、BCE，共 6 個（B 因 BC:3、E 因 BE:2、AB 因 ABC:2、BE 與 CE 因 BCE:2 都不閉合）。極大：ABC、BCE，共 2 個。

7.4 情境應用題

1. 用 Apriori 跑大型量販店資料，min_sup 設太低導致跑不完、結果超過百萬筆，可以怎麼調整？

看解答
提高 min_sup 減少候選；只回報閉合或極大頻繁項目集來壓縮結果；或改用 W6 的改良法（Hash-based、Transaction reduction、Partitioning、Sampling）或 FP-Growth。

8. 一頁速記

  1. 關聯規則 X⇒Y：X、Y 非空且不相交，描述共同出現不是因果。
  2. 支持度 = sup(X ∪ Y) / |D|；信賴度 = sup(X ∪ Y) / sup(X)。
  3. 強規則 = 同時過 min_sup 與 min_conf。
  4. 兩階段：先找頻繁項目集，再產生規則；k-項目集可產生 2^k − 2 條規則。
  5. Apriori 性質：頻繁的子集必頻繁；不頻繁的超集必不頻繁。
  6. Apriori 每層：連接（前 k−1 項相同）→ 剪枝（查 k-子集）→ 掃描計數 → 留下 ≥ min_sup。
  7. 剪枝發生在計數之前，節省掃描資料庫的成本。
  8. 閉合：沒有同支持度的超集（無損）；極大：沒有頻繁的超集（有損）；極大 ⊆ 閉合 ⊆ 頻繁。
  9. 算信賴度時分母是前項，注意 2/3 = 66.7% 與門檻的比較。
  10. Apriori 缺點：多次掃描、候選爆炸；W6：Hash、Transaction reduction、Partitioning、Sampling、FP-Growth。
